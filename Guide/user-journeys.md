# Campus 360 — User Journeys

## Journey model

> **Trigger → Entry → Decision → Action → Outcome → Return**

Do not design primarily as Page → Page → Page.

## Public journeys

### A. Verify breaking campus news

WhatsApp rumor  
→ direct Breaking URL  
→ see what happened, campus, timestamp, verification  
→ read current update  
→ share  
→ return later  
→ full Article available.

Success:
- answer in seconds;
- no login;
- no interstitial;
- stable URL.

### B. Find an internship

Google/Home/Search  
→ Opportunities  
→ Internships  
→ filter  
→ detail  
→ deadline/eligibility/source  
→ Apply externally.

Success:
- current;
- credible;
- open;
- relevant;
- working link.

### C. Discover an event

Home/Campus  
→ Events  
→ This Week/Weekend  
→ detail  
→ time/venue/price/organizer  
→ ticket/directions  
→ after event, same URL can expose coverage.

### D. Watch full Hotseat episode

TikTok/Instagram clip  
→ direct Episode URL  
→ play  
→ guest context  
→ related clips  
→ Programme page  
→ other Episodes.

### E. Browse my campus

Select university/campus  
→ Campus hub  
→ Latest / Events / Opportunities / Watch / Guide.

Preference is persistent but non-exclusive.

### F. Find a campus service

Search “printing Makerere”  
→ Vendor result  
→ profile  
→ WhatsApp/Call/Directions.

Success metric:
- measurable referral.

### G. Fresher discovery

Google/social  
→ Fresher Guide/Campus hub  
→ orientation/culture/events/services/videos  
→ revisit after arrival.

### H. Search

Search  
→ entity suggestions  
→ grouped results  
→ filters  
→ direct entity.

No-result queries are logged.

## Editorial journeys

### Breaking correspondent

Event occurs  
→ mobile Newsroom  
→ Submit Breaking  
→ urgent editor notification  
→ editor verifies  
→ short update published  
→ full Article developed.

### Standard journalist

Story Idea  
→ Assignment  
→ Reporting  
→ Draft  
→ Submit  
→ Review  
→ Changes Requested if needed  
→ Verification  
→ Ready  
→ Scheduled/Published  
→ Distribution  
→ Updates/Corrections.

### Editor

My Desk  
→ Breaking Desk/Review Queue  
→ inspect sources/verification/risk  
→ request changes / approve / escalate / publish  
→ activity captured.

### Programme producer

Programme Desk  
→ Episode  
→ production metadata  
→ video processing  
→ review  
→ schedule  
→ publish  
→ derivatives.

## Commercial journeys

### Sponsor

Business section  
→ audience/media products  
→ enquiry  
→ lead  
→ proposal  
→ campaign  
→ deliverables  
→ performance  
→ report  
→ renewal.

### Vendor

List Your Business  
→ verification  
→ listing setup  
→ active placement  
→ referral measurement  
→ renewal.

### Employer

Post Opportunity  
→ submission  
→ verification  
→ publish  
→ optional promoted campaign  
→ application traffic.

## Management journeys

### Executive
Control Overview → anomaly → drill-down → action → resolution.

### Commercial manager
Campaign alert → campaign → incomplete deliverables → owner/due date → editorial deep link if needed.

### Platform admin
Health warning → subsystem → failed jobs/index → retry/escalate → audit.

## Priority

### Critical
- breaking/news;
- search;
- campus filtering;
- opportunities;
- watch/programmes;
- journalist publishing;
- editor verification.

### High
- events;
- sharing;
- vendor discovery;
- campaign management;
- platform health.

### Later
- accounts;
- personalized feed;
- comments;
- creator following;
- marketplace;
- social messaging.

## Prototype targets

- verify breaking: <30 sec
- switch campus: <20 sec
- find internship: <60 sec
- reach latest Hotseat: <30 sec
- find event: <45 sec
- find vendor: <60 sec
- submit breaking: <2 min
- editor finds urgent report: <20 sec
- commercial manager finds late deliverable: <30 sec
- admin finds failed job: <30 sec
